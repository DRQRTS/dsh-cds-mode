# 放行清单（Release Checklist）

> 铁律 L7 的推论：**放行是一个动作，不是一个数字。**
> `S1/S2 = 0` 只说明「没找到致命 bug」，**不说明可以交付**：
> 未验证项可能成堆、安全报告可能根本没人写、回归基线可能已经漂了。
> 本文件规定 `DONE` 门禁的**硬勾选项**：**任一项未勾，不得进 DONE。**

---

## 一、为什么需要它

`CORE.md` 的 DONE 门禁原文是「测试零 bug，或用户确认接受残余风险」——
这是**单一数字门槛**，可以被一个数字满足，也可以被一句话绕开。
`workflow/01-new-project.md` 的交付报告有 7 节结构，但只要求「列出」未验证项，
**列出 = 诚实，不等于放行**：报告里写着「未验证项 12 条」，仍然可以照发。

于是出现最常见的失败形态：**流程全都走完了，东西不能跑。**

本清单把「可以交付」拆成七条**可判定、可留痕**的条件，由晨在交付前逐条勾选。
它不增加人格、不增加轮次，只增加**一次诚实的自检**。

---

## 二、七条硬勾选项

```
[ ] 1. 未验证项 = 0，或用户已书面接受（留痕于 .cds/decisions.md）
[ ] 2. C4 安全报告齐备（极小 / 小规模按 B6 的分级要求，见 CORE §5）
[ ] 3. D4 复验通过（AI 味项，见 CORE §10.1 复验门禁）
[ ] 4. 回归基线一致（D1 已跑，且与上一轮基线可逐条比对）
[ ] 5. 可运行产物冒烟通过（不是「编译通过」，是「跑起来能用」）
[ ] 6. known-issue 每条有等级与理由（按 L3，不许裸列）
[ ] 7. 收敛数字经 B4 独立复算（不读 D6 汇总，见 B2）
```

### 逐条说明

| # | 勾选条件 | 判定依据 | 未勾时的动作 |
|---|---|---|---|
| **1** | 未验证项清零，或**用户本人**在 `decisions.md` 留痕接受 | `decisions.md` 有对应条目 + 用户确认原文 | **不得交付**；回阶段 6 补验，或请用户显式接受 |
| **2** | C4 报告存在，或按规模分级**明确记录豁免理由** | `security/` 下有报告，或 `decisions.md` 有分级豁免记录 | 回 BUILD 补 C4；**豁免必须有理由，不许静默跳过** |
| **3** | D4 对 AI 味项给出「通过」结论 | `tests/bugs-D4-<轮次>.md` 的「复验结论」段 | 回 C1/C3 修复；**D4 未签，AI 味项不算关闭**（CORE §10.1） |
| **4** | D1 本轮跑过基线，且差异**逐条有解释** | `tests/bugs-D1-<轮次>.md` 的基线比对段 | 补跑 D1；**基线漂移未解释 = 未收敛** |
| **5** | 有可运行产物，且**实际执行过一次**基本路径 | 交付报告第 2 节「怎么用」的命令**真的跑过** | 补冒烟；**这一条最容易被自欺——「应该能跑」不算跑过** |
| **6** | 每条 known-issue 带 S1–S5 等级 + 一句理由 | 交付报告第 4 节 | 补等级与理由；**裸列问题清单等于没列** |
| **7** | 收敛数字由 B4 独立复算得出，与 D6 汇总一致 | 两份数字比对（B2 要求 B4 不读 D6 汇总） | 补 B4 复算；**两份数字不一致 = 未收敛** |

## 三、执行方式

**执行者**：晨（在阶段 10 交付前，一次完成）
**留痕位置**：交付报告**开头**加一节「放行清单」，逐条写勾选状态与依据坐标。

**规则**：

1. **逐条勾选，不打总包**。不许写「以上全部满足」——每条必须有自己的判定依据。
2. **未勾的项必须写明动作**（补验 / 请用户接受 / 豁免并记理由），不许留空。
3. **勾选结果写进交付报告**，用户看得见「哪些是验过的、哪些是接受的、哪些是豁免的」。
4. **豁免要留痕**：任何靠「用户接受」或「按规模豁免」通过的项，
   必须在 `.cds/decisions.md` 有对应条目，写明**接受/豁免的具体内容与理由**。
5. **这是自检，不是新的审批环节**。晨自己勾，不需要用户逐条批准；
   用户看到的是**勾选结果**，而不是被要求再答一遍题。

---

## 四、常见自欺（点名）

写这张清单时最容易被自己的话术骗过去。以下四种表述**不算勾选**：

| 自欺表述 | 为什么不算 | 正确做法 |
|---|---|---|
| 「未验证项已列出」 | 列出 ≠ 清零 ≠ 用户接受 | 清零，或拿到用户书面接受 |
| 「安全层按规模豁免了」 | 豁免没写理由 = 静默跳过 | `decisions.md` 写明豁免依据（B6 分级） |
| 「D4 说没问题了」 | 频道口头结论不留痕 | D4 写在产物里的「复验结论」段 |
| 「应该能跑」 | 推测不是执行 | 交付报告第 2 节的命令**实际执行过** |

**一句话判据**：**每一勾都要能指到一个文件、行号或原文。指不到，就是没勾。**

## 五、与收敛判据的关系（别混淆）

| | 收敛判据（`01-new-project.md` 阶段 9） | 放行清单（本文件） |
|---|---|---|
| **回答的问题** | 「bug 修完没有？」 | 「**东西能不能交？**」 |
| **判据** | S1/S2 = 0 且连续两轮无新增 | 七条硬勾选全过 |
| **执行时点** | 每轮测试后 | 交付前一次 |
| **执行者** | D6 汇总 + B4 复算 | 晨 |

**两者都过才算完成。** 收敛了但放行清单没过，说明「没 bug」是假象（例如根本没跑过）；
放行清单过了但没收敛，说明不该急着交。**同时满足才进 DONE。**
