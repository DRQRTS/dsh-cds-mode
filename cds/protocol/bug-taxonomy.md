# Bug 分类法（五级分类法 + 类型分类法）

> D6 的核心工具。所有 bug 必须**同时**带上 `level`（五级）与 `type`（类型）两个标签。

---

## 一、五级分类法（按紧急程度）

| 等级 | 名称 | 定义 | 典型例子 | 响应要求 |
|---|---|---|---|---|
| **S1** | 阻断 / 致命 | 项目不可运行、数据不可逆丢失、安全被直接攻破、对外服务全挂 | 启动即崩溃；数据库被清空；任意人可读全部用户数据 | **立即停止其他工作**，当轮必须修 |
| **S2** | 严重 | 核心功能不可用，或**静默产生错误数据**，或高危安全问题 | 提交后数据丢失；金额算错但界面正常；越权读他人数据 | 本版必须修，**不得带入 DONE** |
| **S3** | 中等 | 非核心功能不可用，或核心功能有明显但不致命缺陷 | 导出功能报错；筛选条件偶发失效；中危安全问题 | 本版修，或经用户确认后降级 |
| **S4** | 轻微 | 体验、性能、一致性问题，有替代路径 | 布局错位；按钮位置不顺手；同类弹窗按钮顺序不一致；慢 | 可排期，可跨版本 |
| **S5** | 建议 / 主观 | 改进建议、风格意见、可争议项 | 颜色刺眼；文案可以更好；命名可以更短 | 记录即可，不必修 |

### 升级规则（必须升级的情形）

| 情形 | 处理 |
|---|---|
| 静默错误数据（不报错但结果错） | **至少 S2**，与是否核心功能无关 |
| 影响多个用户的数据问题 | **至少 S2** |
| 安全问题可被远程未认证利用 | **S1** |
| 问题只在特定条件下出现，但该条件在真实使用中常见 | **升一级** |
| 问题会导致用户做出错误决策 | **升一级** |
| 同一个 bug 被"修复" 3 次仍未修好 | **升一级** + 触发 CB-6 |

### 降级规则（可以降级的情形）

| 情形 | 处理 | 附加要求 |
|---|---|---|
| 有明确且用户知晓的替代路径 | 可降一级 | 必须在报告中写明替代路径 |
| 触发条件在真实使用中极罕见（并说明为什么罕见） | 可降一级 | 必须给出触发概率依据 |
| 已有其他修复会顺带解决 | 可降一级 | 必须指明依赖哪个修复 |

**降级禁令**：
- S1、S2 **不得降级为 S3 及以下**。
  > 早先只禁到 S4/S5，是个**后门**：S3 不阻断交付（见 `CORE.md` 第五节），
  > 于是把一条 S1 标成 S3，就能合法制造「零 S1/S2」的虚假收敛。禁令必须覆盖整条降级路径。
- **S1/S2 的定级与降级必须双签**：报告人 + 一位**非报告人**的 D 人格，任一方不同意则维持原级。
  > 单签（原先只要求 D6）等于让一个人既出数又定级，见 `D6-分类汇总者.md` 的等级校准职责。
  > 双签把「压级」的串谋成本从 1 人抬到 2 人，且强制留痕。
- 任何降级必须写明理由 + 双签记录，并记入 `decisions.md`；
- 为了让数字好看而降级，属严重违规（对应 L3 铁律的变体）。

## 二、类型分类法（按 bug 性质）

类型代码用 `T-<组>-<序号>`，便于统计聚簇。

### 功能类

| 代码 | 名称 | 判据 |
|---|---|---|
| `T-FN-01` | 逻辑错误 | 代码读起来对，跑起来不对 |
| `T-FN-02` | 边界条件 | 空/满/超长/零/负数/首尾元素 |
| `T-FN-03` | 状态不一致 | 界面与数据、两处状态不同步 |
| `T-FN-04` | 并发 / 竞态 | 重复提交、双写、顺序依赖 |
| `T-FN-05` | 错误处理缺失 | 失败被吞、报错不可读、无法恢复 |
| `T-FN-06` | 幂等性缺失 | 同一操作执行两次结果不同 |
| `T-FN-07` | 数据一致性 | 事务边界、级联删除、孤儿记录 |
| `T-FN-08` | 兼容性 | 跨浏览器/设备/版本/平台不一致 |
| `T-FN-09` | 时间与时区 | 时区、夏令时、跨天、闰年、时钟漂移 |
| `T-FN-10` | 序列化 / 编码 | 字符集、转义、精度、大整数 |

### 安全类

| 代码 | 名称 |
|---|---|
| `T-SEC-01` | 认证缺陷（绕过、会话固定、令牌可预测） |
| `T-SEC-02` | 授权缺陷（越权 / IDOR / 提权） |
| `T-SEC-03` | 注入（SQL / NoSQL / 命令 / 模板 / XSS / SSRF） |
| `T-SEC-04` | 信息泄露（堆栈、调试端点、源映射、密钥、备份文件） |
| `T-SEC-05` | 传输与存储（明文、弱哈希、Cookie 属性） |
| `T-SEC-06` | 请求伪造（CSRF / 点击劫持 / 开放重定向） |
| `T-SEC-07` | 依赖与配置（已知漏洞版本、CORS 通配、CSP 缺失、默认口令） |
| `T-SEC-08` | 业务逻辑漏洞（负数金额、超量领取、跳过步骤） |
| `T-SEC-09` | 滥用与限流缺失 |

### 性能与资源类

| 代码 | 名称 |
|---|---|
| `T-PF-01` | 响应过慢（超阈值） |
| `T-PF-02` | 内存泄漏 / 增长 |
| `T-PF-03` | N+1 查询 / 全表扫描 |
| `T-PF-04` | 无界增长（日志、缓存、队列、磁盘） |
| `T-PF-05` | 主线程阻塞 / 卡顿 / 布局抖动 |
| `T-PF-06` | 包体积 / 首屏体积过大 |
| `T-PF-07` | 无效请求 / 重复请求 / 缓存未利用 |

### 体验与人因类

| 代码 | 名称 |
|---|---|
| `T-UX-01` | 视觉缺陷（对齐、间距、层级、截断、溢出） |
| `T-UX-02` | 可读性（对比度、字号、行宽、深浅色） |
| `T-UX-03` | 操作不协调（位置、焦点顺序、需滚动、点不中） |
| `T-UX-04` | 反馈缺失（点击无响应、无加载态、无成功提示） |
| `T-UX-05` | 一致性（同类操作不同表现） |
| `T-UX-06` | 无障碍（键盘、屏幕阅读器、色彩依赖） |
| `T-UX-07` | 文案问题（错误提示、空状态、说明不清） |
| `T-UX-08` | 响应式（小屏、大屏、缩放 200%） |

### 工程与可维护类

| 代码 | 名称 |
|---|---|
| `T-EN-01` | 命名不承载信息 |
| `T-EN-02` | 过度抽象 / 无用包装 |
| `T-EN-03` | 重复代码 / 复制粘贴 |
| `T-EN-04` | 注释与实现不符 / 注释复述代码 |
| `T-EN-05` | 死代码 / 未使用依赖 / 注释掉的代码 |
| `T-EN-06` | 配置硬编码 / 环境耦合 |
| `T-EN-07` | 测试缺失或失效 |
| `T-EN-08` | 构建与部署脚本缺陷 |
| `T-EN-09` | 文档与实际不符 |

### AI 味类（D4 专属）

| 代码 | 名称 |
|---|---|
| `T-AI-01` | 代码命名模板化（Service/Manager/Handler 泛滥） |
| `T-AI-02` | 空转文本（排比、三段式、信息量为零） |
| `T-AI-03` | emoji 滥用 / 破折号堆砌 / 感叹号 |
| `T-AI-04` | 视觉定式（三件套首屏、卡片网格、紫渐变玻璃拟态） |
| `T-AI-05` | 与用户文化语境不符（译制腔、语言混杂） |
| `T-AI-06` | 样板化注释与文档（"本项目的优势在于高效、稳定、易用"） |
| `T-AI-07` | 无观点的设计决定（任何同类项目都可原样替换） |

### 长远腐化类（D3 专属）

| 代码 | 名称 |
|---|---|
| `T-LT-01` | 数据增长导致退化 |
| `T-LT-02` | 依赖腐化（弃用、停更、被黑） |
| `T-LT-03` | 无界资源增长（磁盘、内存、连接数） |
| `T-LT-04` | 知识腐化（没人记得为什么这样写） |
| `T-LT-05` | 第三方服务变脸（限流、涨价、改协议、下线） |
| `T-LT-06` | 配置漂移（生产与开发不一致） |
| `T-LT-07` | 静默数据腐化（不报错的慢性错误） |
| `T-LT-08` | 缓存与陈旧状态（跨天、夏令时、TTL 边界） |

### 回归类（接手项目 / 重构专用）

| 代码 | 名称 |
|---|---|
| `T-REG-01` | 既有功能行为变化 |
| `T-REG-02` | 既有接口契约变化 |
| `T-REG-03` | 既有数据格式变化 |
| `T-REG-04` | 性能回退 |
| `T-REG-05` | 既有用户习惯被破坏 |

### 2.1 类型 → 负责视角（`owner`，**v1.7.0 新增**）

> **为什么需要这张表**：早先每个类型码只定义了"是什么"，**没定义"谁负责发现"**。
> 于是若干类型（时区、序列化、性能、无障碍、配置硬编码、配置漂移）**没有任何 D 视角归属**——
> 它们不是"没人测到"，而是"**没人被指派去测**"，属于结构性盲区。
>
> **本表只做归属，不新增人格**（新增 D7 = 再增一张卡 = 又一次缓存失效，且违反 v1.6.0「治吹毛求疵」的方向）。
> 做法是**把无主类型指配给现有视角**：谁的职责最贴近，就归谁。

| 类型组 | 代码前缀 | **owner** | 理由 |
|---|---|---|---|
| 功能类 | `T-FN-*` | **D1** | 代码级跑测覆盖逻辑/边界/状态/并发 |
| ↳ 时间与时区 | `T-FN-09` | **D1**（D3 复核） | D1 跑得出，D3 判断"跨天/夏令时三个月后是否腐化" |
| ↳ 序列化 / 编码 | `T-FN-10` | **D1** | 边界与精度问题的直接观察者 |
| 安全类 | `T-SEC-*` | **D5** | 红队唯一视角；D1 只做"未授权路径"的旁证 |
| 性能与资源类 | `T-PF-*` | **D1**（D3 复核 `T-PF-04`） | 响应/泄漏/阻塞由跑测测得；**无界增长归 D3**（它是"三个月后"的问题） |
| ↳ 包体积 / 首屏 | `T-PF-06` | **D2** | 首次加载体验，实测才准 |
| 体验与人因类 | `T-UX-*` | **D2** | 实机体验专属 |
| ↳ 无障碍 | `T-UX-06` | **D2** | 键盘/读屏是实机操作问题 |
| 工程与可维护类 | `T-EN-*` | **D1** | 命名/抽象/死代码/注释由读代码发现 |
| ↳ 配置硬编码 | `T-EN-06` | **D1**（D3 复核） | 硬编码在代码里可见；**环境耦合的后果归 D3** |
| ↳ 测试缺失/失效 | `T-EN-07` | **D1** | 跑测时即可发现"没测到" |
| ↳ 文档与实际不符 | `T-EN-09` | **D1** | 对照实现与文档 |
| AI 味类 | `T-AI-*` | **D4** | 专属否决权 |
| 长远腐化类 | `T-LT-*` | **D3** | 专属视角 |
| ↳ 配置漂移 | `T-LT-06` | **D3** | "生产与开发不一致"是时间维问题 |
| 回归类 | `T-REG-*` | **D1** | 回归基线的持有者（见 `personas/D1-代码级跑测.md`） |

**用法**：D6 在汇总时按本表检查**每个出现的类型码是否有其 `owner` 视角的报告**。
若某类型只有 0 条报告、且**对应 owner 本轮未派**，D6 必须在汇总里写一行：
「`<类型码>` 本轮无 owner 覆盖」——**这是"盲区"，不是"没问题"**。二者在报告里必须区分。

> **注意**：本表是**发现责任**的归属，不改判定权——等级的定级/降级规则见第一节（含 S1/S2 双签）。

## 三、优先级排序规则（D6 使用）

排序键（依次比较）：

```
1. level        S1 > S2 > S3 > S4 > S5
2. 影响面       受影响用户比例 × 频率
3. 静默性       静默错误 > 显式报错
4. 修复成本     成本低者优先（同等条件下）
5. 阻塞性       是否阻塞其他 bug 的修复
```

**特殊规则**：
- 若某 bug 是其他多个 bug 的**共同根因**，优先级**提升一位**（修一个顶多个）。
- 若某 bug 会导致**用户做出错误决策**，优先级**提升一位**。
- 安全类 S1/S2 一律置顶。

## 五、类型统计的用途

D6 在给出汇总后，额外输出**分布观察**（供 B4 判断结构性问题）：

| 观察 | 含义 | 建议动作 |
|---|---|---|
| 某一 type 占比 > 30% | 该类问题是系统性缺陷 | 不是修 bug，是改设计 |
| `T-FN-04`（并发）反复出现 | 并发模型有结构性缺陷 | 回 DESIGN 检查状态模型 |
| `T-AI-*` 反复出现 | 产出风格漂移 | 让 B3/D4 出风格治理方案 |
| `T-LT-*` 集中出现 | 缺乏长期工程约束 | 让 C4/E6 出运维约束 |
| `T-REG-*` 出现 | 改动破坏了既有行为 | 提高 C3 守卫强度 |
| 修复成本持续偏高 | 耦合度过高 | 安排轻量化/重构轮 |

**规则**：只要出现「某一 type 占比 > 30%」，D6 **必须**在汇总里显式提出"这是设计层问题"的判断，并建议晨走 TRIAGE 的归因分支。
