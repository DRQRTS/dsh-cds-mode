# 实时作战（I 组主导）

> **适用时机**：攻击**正在发生**时。
> **主导者**：I-web1（实时防御指挥）。
> **与常规流程的区别**：常规流程可以等证据齐；实时作战**先止损，后补证据**。

---

## 一、触发条件

满足任一即进入实时作战：

| # | 触发 | 来源 |
|---|---|---|
| 1 | B-web1 报"正在进行中"的告警 | B-web1 |
| 2 | B-web5 发现持续外传 / 活动 C2 会话 | B-web5 |
| 3 | 蜜标被触发 | I-web3 |
| 4 | 勒索加密行为被检测到 | B-web1 / EDR |
| 5 | 用户直接告知"正在被攻击" | 晨 |

**触发后不由晨转达**：B-web1 / B-web5 / I-web3 **直接推 I-web1**（同伴频道），同时抄送晨备查。**这是"不经晨传话"最关键的一处** —— 攻击进行中，多一次中转就是多一段延时。

---

## 二、秒级—分钟级—小时级

| 时间 | 必须完成 | 谁 |
|---|---|---|
| **≤60 秒** | 态势研判三句话（在打什么 / 打到哪了 / 下一步），并发出第一批指令 | I-web1 |
| **≤5 分钟** | 出站方向切断或白名单化（止损优先） | I-web2 |
| **≤15 分钟** | 横向阻断 + 欺骗诱饵上线 + 溯源启动 | I-web2 / I-web3 / I-web4 |
| **≤60 分钟** | 遏制范围确定（按取证分级）、业务影响评估、策略门判定 | C-web3 / C-web4 / D-web1 |
| **≤4 小时** | 攻击面控制住，进入常规响应流程 | 全体 |
| **事后** | 取证完整性补齐、溯源深化、报告成文 | B-web2 / I-web4 / D-web2 |

**注意**：上表是**目标**，不是承诺。做不到要说明卡在哪 —— **卡点信息比"已完成"更有价值**（D-web2 复盘要的就是这个）。

---

## 三、并行派发（硬要求）

攻击进行中**禁止串行**。四条线必须同批发出：

```yaml
# 同批并发，一次派完
to: I-web1   # 指挥（本身即主导者）
to: I-web2   # 阻断
to: I-web3   # 欺骗
to: I-web4   # 溯源
```

**I-web5（反击）不走这个批次。** 它需要 `D-web1 策略门` + `用户权限审批` **双通过**，单独走，且**不阻塞上面四条线**。

**反例（禁止的做法）**：

```
❌ 先派 I-web2，等它回来再派 I-web4
   → 溯源晚 5 分钟开始，攻击者可能已经换基础设施

❌ 等 B-web2 取证完整再决定阻断什么
   → 取证完整可能需要几小时，数据早出去了

❌ 因为要申请反击授权，先把阻断停一下
   → 反击是可选动作，阻断是必须动作，不能互相阻塞
```

## 四、止损优先于溯源

**这是实时作战最容易搞错的一点。**

| 优先级 | 做什么 | 理由 |
|---|---|---|
| **P0** | 切断正在发生的数据外传 | 数据出去就回不来了 |
| **P0** | 阻断正在进行的横向移动 | 每多一分钟，多一台机器沦陷 |
| **P1** | 溯源与画像 | 有价值，但**不紧急**——基础设施不会跑掉 |
| **P1** | 欺骗诱导 | 争取时间，与 P0 并行 |
| **P2** | 取证细节补齐 | 可以在控制住之后做 |
| **P2** | 完整复盘 | 事后 |

**常见错误**：追着最响的告警跑，忽略了另一条"安静但正在外传"的线。
**I-web1 的具体做法**：态势研判时**先按"是否正在造成不可逆损失"排序**，而不是按 severity 排序。

## 五、升级与降级

### 升级（往更重的处置走）

| 条件 | 动作 |
|---|---|
| confirmed 资产数增加 | 扩大遏制范围（按分级，不按感觉） |
| 出现加密行为 | **立即**升到最高优先级 + 通知晨准备灾备 |
| 外传量持续增加 | 从"限速"升到"出站白名单" |
| 发现攻击者已进入核心段 | 触发业务连续性预案（C-web4） |
| 攻击手段超出当前授权 | **停下**，经晨申请扩展授权 |

### 降级（回到常规流程）

| 条件 | 动作 |
|---|---|
| 外传已切断且 30 分钟无复发 | 从实时切回常规响应 |
| 横向已阻断且 C-web2 验证通过 | 解除实时作战状态 |
| 攻击者停止活动 2 小时（覆盖其活跃时段） | 转常规跟进 |

**降级也要留痕**，说明依据。

---

## 六、实时作战的停止信号

**任何人**都可以发出停止信号，**I-web1 必须在 1 分钟内响应并停止相关动作**。

| 谁可发 | 什么情况下 |
|---|---|
| 晨 | 用户要求停止 / 授权被撤回 |
| D-web1 | 发现动作越界 |
| D-web4 | 涉及个人数据且未评估 |
| C-web4 | 业务影响超出可承受 |
| I-web1 | 自身判断风险不可控 |

**停止信号不是失败**，是纪律。事后由 D-web2 复盘停止是否恰当 —— **宁可错停，不可错做**。

## 七、实时作战的自检清单（I-web1 每轮过一遍）

- [ ] 态势三句话给出了吗？
- [ ] 优先级是按"不可逆损失"排的，还是按 severity 排的？
- [ ] 四条线同批派出了吗？有没有卡在串行？
- [ ] 我把"止损"和"溯源"分开了吗？有没有为追黑客拖延止损？
- [ ] 阻断动作**过了 D-web1** 吗？有没有拿"紧急"当理由绕过？
- [ ] 反击决策是**提交**给 D-web1 和晨，还是我自己拍板了？
- [ ] 授权范围外的东西，我碰了吗？
- [ ] 我问过 C-web4 业务影响吗（涉及重档处置时）？
- [ ] 我问过 D-web4 了吗（涉及个人数据时）？
- [ ] 我的动作**可回滚**吗？说得出回滚步骤与耗时吗？
- [ ] 留痕齐全吗（时间含时区 / 目标 / 参数 / 结果）？
- [ ] 有没有"顺手多封几个"？
