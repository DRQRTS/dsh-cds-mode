# 授权边界（授权书与越界判定）

> **护栏 1：无授权不扫描、不入侵、不响应、不测试、不反击。**
> **护栏 11：F 组与 I-web5 所有动作必须在书面授权范围内，越界即停。**

---

## 一、授权书模板（`.cds/authorization.md`）

**这是本工作流唯一的准入依据。** 晨向用户索取权限后由此落盘。

```yaml
authorization:
  id: AUTH-2026-011
  granted_by: <用户标识>
  granted_at: 2026-10-01T01:00:00+08:00
  expires_at: 2026-12-31T23:59:59+08:00

  # 1. 授权边界 —— 逐项可核对，不许写"相关资产"
  scope:
    assets:
      - "10.0.20.0/24"
      - "app.example.com"
      - "aws-account:1234567890（仅 prod 账号）"
    excluded:
      - "10.0.30.0/24（财务段，明确排除）"
      - "任何第三方托管服务"

  # 2. 时间窗口 —— 含时区
  windows:
    - { start: "2026-10-01T02:00:00+08:00", end: "2026-10-01T06:00:00+08:00" }
    - { start: "2026-10-08T02:00:00+08:00", end: "2026-10-08T06:00:00+08:00" }
  blackout:
    - "每日 09:00–21:00（业务高峰）"
    - "月末最后两天（结算期）"

  # 3. 禁止动作 —— 硬红线，无紧急程度可突破
  forbidden:
    - "任何写操作（数据变更、配置修改）"
    - "重启或下线任何生产服务"
    - "访问或导出真实用户数据"
    - "对第三方系统发起任何请求（含探活）"
    - "拒绝服务类测试"

  # 4. 成功标准
  success_criteria:
    - "确认攻击是否成功、影响范围明确"
    - "给出可执行的修复建议并验证有效"

  # 5. 反击授权
  countermeasures:
    allowed: true
    types: ["infrastructure-tagging", "legal-evidence", "cert-report"]
    denied_types: ["active-scan-of-attacker", "any-intrusion", "any-ddos"]
    note: "仅限我方可见的被动信息；不主动接触对方系统"
    approver: "<用户标识>"

  # 6. 合规与隐私
  compliance:
    frameworks: ["等保三级", "个保法"]
    personal_data_involved: true
    dweb4_required: true

  # 7. 应急
  emergency_contact: "<联系人>"
  stop_signal: "在态势面板点击『全部停止』，或口头向晨说明"
```

## 二、授权书必须"逐项可核对"

| 写法 | 评价 |
|---|---|
| `assets: ["相关系统"]` | ❌ **不可核对**，D-web1 无法判定 |
| `assets: ["10.0.20.0/24", "app.example.com"]` | ✅ 可逐项核对 |
| `forbidden: ["注意安全"]` | ❌ 不是禁止动作 |
| `forbidden: ["禁止任何写操作", "禁止重启生产服务"]` | ✅ 可判定 |
| `windows: ["工作时间之外"]` | ❌ 无具体时段 |
| `windows: [{start, end}]` + `blackout` | ✅ 可判定 |

**授权模糊时 D-web1 从严（护栏 9）** —— 这不是 D-web1 保守，是**授权方的责任**：写不清就没法安全执行。

## 三、越界判定（五类）

**"越界"不只是"做了范围外的事"。** 以下五类都算越界，都要停。

| # | 类型 | 例子 | 处理 |
|---|---|---|---|
| 1 | **范围外** | 扫描不在 `assets` 里的 IP | **立即停** + 上报 |
| 2 | **窗口外** | 在 `blackout` 时段执行 | **立即停** + 上报 |
| 3 | **撞禁止动作** | 做了 `forbidden` 里的写操作 | **立即停** + 上报（严重） |
| 4 | **判定依据变化** | 目标 IP 归属变化（如变成了共享出口） | **立即停** + 重新判定 |
| 5 | **超出动作类型** | 授权允许"标记"但做了"主动探测" | **立即停** + 上报 |

**第 4 类最容易被忽略，也最重要。**

> **实例（I-web5 的真实处置）**：执行中对 4 个 C2 IP 做基础设施标记。中途 I-web4 更新情报，发现其中 1 个 IP 实际是**某云服务商的共享出口**（非攻击者独占）。**立即停止对该 IP 的所有动作并移除**。
> 理由：不是"范围外"，而是**范围判定的依据变了** —— 原判定"这是攻击者基础设施"不再成立，处置它会误伤无辜第三方。

---

## 四、"越界即停"的具体含义

| 是 | 不是 |
|---|---|
| 立刻停止**当前动作** | 把当前动作做完再停 |
| **保留已做的记录**（不删痕迹） | 清理痕迹（那是掩盖） |
| **上报** I-web1 + D-web1 | 自己判断"问题不大"继续 |
| **重新走策略门** | 自己修正后继续 |
| 不是失败，是纪律 | 不是"我搞砸了" |

**停下来的成本，永远低于做错的成本。**

---

## 五、授权的变更与撤回

| 情况 | 处理 |
|---|---|
| **扩大授权** | 晨向用户申请 → 更新 `.cds/authorization.md` → 重新走策略门。**旧授权不自动扩展** |
| **缩小授权** | 立即生效。已在进行的动作若超出新范围 → **立即停** |
| **撤回授权** | 立即生效。**所有动作停止**，包括已排队未执行的 |
| **授权过期** | 视同无授权。**过期后不得执行任何动作**，需重新授权 |

**撤回是即时的。** 不存在"这个动作已经批了所以做完" —— 撤回意味着**连已批的也停**。

## 六、五组红线速查（谁最容易被越界）

| 组 | 最易越界的行为 | 防范要点 |
|---|---|---|
| **A-web1** | 扫描范围外资产 | 每轮先列清单，范围外**只登记不探测** |
| **A-web3** | 社会工程 / 下载泄露数据 | 只有"看"没有"问"；泄露数据**只报匹配数不搬运** |
| **B-web4 / F-web3** | 样本外传 | **禁止外传**，需协助时只描述行为 |
| **F 组** | "顺便试试" | 授权书没有的一律不碰，写进"建议扩展" |
| **I-web2** | "顺手多封几个" | 批了 3 个就封 3 个，多出的走追加申请 |
| **I-web5** | 主动接触对方系统 | 只读 + 公开信息查询；**"只 ping 一下"也算访问** |
| **G-web2** | 自动化越过审批边界 | 熔断三件套 + 预授权清单边界 |
| **G-web3** | 工具里加需求外功能 | 建议写进文档，不直接实现 |

## 七、自检清单（每个 Agent 每轮过一遍）

- [ ] 我读过 `.cds/authorization.md` 了吗？还是凭印象？
- [ ] 我要动的目标**逐项**在 `assets` 里吗？
- [ ] 现在是 `windows` 内、`blackout` 外吗？
- [ ] 我要做的动作撞 `forbidden` 了吗？
- [ ] 我做的动作类型在授权列举范围内吗？（如"标记"vs"探测"）
- [ ] 范围判定的**依据**变了吗？（归属、解析、所有权）
- [ ] 我有没有"顺便"做了什么？
- [ ] 授权过期了吗？
- [ ] 授权被缩小或撤回了，我知道吗？
- [ ] 我的动作**过策略门**了吗？
- [ ] 如果越界了，我**立刻停**了吗？还是想"做完再说"？
- [ ] 停下后我**上报**了吗？还是自己判断"问题不大"？
