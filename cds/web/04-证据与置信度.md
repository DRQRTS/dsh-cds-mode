# 证据链与置信度（可解释性）

> **护栏 5：每个结论必须附带证据链与置信度。**
> 这不是学术要求，是**操作要求** —— 没有置信度的结论会让决策者按最坏情况处置（过度遏制），或者按最好情况处置（漏掉攻击）。

---

## 一、证据链三元组（最低要求）

每条结论必须能回答三个问题：

| 问题 | 对应 | 缺失后果 |
|---|---|---|
| **从哪来** | 源（日志 / 样本 / 流量 / 情报 / 配置） | 无法复核 |
| **经过什么** | 方法（怎么分析的、什么工具、什么条件） | 无法重复 |
| **得出什么** | 结论 | —— |

**三元组缺一 → 该结论降级为"线索"，不得进入报告结论段。**

---

## 二、证据等级（用于漏洞与逆向类结论）

| 等级 | 判据 | 可用位置 |
|---|---|---|
| `verified` | 实际执行/复现，有直接证据（断点、内存、回包、复现步骤） | 可写进结论段 |
| `inferred` | 从控制流/数据流推断，未实际执行 | 结论段，**须标注** |
| `speculative` | 仅凭字符串/常量/相似性猜测 | **只能作为线索，禁止进结论段** |

**"能打"与"可能能打"必须区分。** 把 `speculative` 写成结论，会导致修复资源投在不存在的问题上，而真问题被忽略。

---

## 三、影响范围的确定性分级（取证类结论）

**B-web2 的核心纪律：三级不可合并。**

| 等级 | 判据 | 处置 |
|---|---|---|
| `confirmed` | 直接证据：进程树 / 网络流 / 文件落地 / 登录事件 | **立即遏制** |
| `probable` | 强间接证据：时间吻合 + 同源 IOC | **监控 + 预备遏制**（方案写好等触发） |
| `possible` | 仅 IOC 匹配 | **只监控** |

**为什么不可合并**：把 `possible` 混进"受影响资产"会让遏制范围虚高。
**实例**：本次事件的 11 台 `possible` 里，事后证明 9 台是误报。若按 11 台全量隔离，会白关 9 台业务系统。

**写法对比**：

```
❌ 受影响资产：18 台
✅ 受影响资产：confirmed 3 台 / probable 4 台 / possible 11 台
   （possible 中 6 台仅命中共用 IOC，该 IOC 历史误报率 40%）
```

## 四、置信度的三个维度

单一"高/中/低"不够用。置信度至少分三面：

| 维度 | 问什么 | 低置信度的表现 |
|---|---|---|
| **来源可靠性** | 数据源本身可信吗？ | 单一来源 / 该源有误报史 |
| **推断强度** | 从证据到结论推了几步？ | 多步推断 / 依赖假设 |
| **一致性** | 与其他独立证据吻合吗？ | 与其他来源冲突 / 无法交叉验证 |

**输出格式示例**：

```yaml
conclusion: "185.x.x.x 是 C2"
confidence:
  source: high          # 两个独立 TI 源 + 我方流量自证
  inference: high       # 三个特征齐（心跳规律 / 协议偏离 / 方向比），无需多步推断
  consistency: high     # 与 B-web5 流量、A-web2 情报一致
overall: high
```

```yaml
conclusion: "该活动属于组织 X"
confidence:
  source: medium        # 情报库来源单一
  inference: low        # 从工具相似推断归属，多步且依赖假设
  consistency: medium   # 部分吻合，但存在反例未排除
overall: low
counter_examples:
  - "若这 4 个 IP 属于公开防弹主机服务，证书复用只反映服务商相同"
org_name_disclosed: false   # 低置信度禁止给出组织名
```

## 五、反例义务（硬要求）

**归因类结论必须写明"什么证据会推翻它"。**

| 结论类型 | 是否必须附反例 |
|---|---|
| 攻击者归因 | **必须** |
| C2 判定 | **必须**（如"若该 IP 属于合法 CDN 则推翻"） |
| 影响范围 `probable` | **必须**（说明什么情况下应降为 `possible`） |
| 漏洞可利用性 | **必须**（写明失败条件） |
| 纯事实记录 | 不强制 |

**为什么**：反例是**决策者的退出条件**。没有反例的结论，一旦错了没人知道该在哪里回头。

## 六、置信度如何驱动决策

置信度不是装饰，它决定**做什么动作**：

| 结论置信度 | 允许的动作 |
|---|---|
| 高 | 可做不可逆动作（前提：过策略门 + 用户权限） |
| 中 | 只做可回滚动作；不可逆动作需补证据 |
| 低 | **只能监控**，不得据此处置 |

**实例**：
- `185.x.x.x` 判定为 C2，**置信度高** → 可封禁（可回滚）
- `evil-cdn.com` **单源、置信度低** → **不封禁**，加监控（A-web2 原话："我建议不要据此封禁"）
- 归因"组织 X" **置信度低** → **不给组织名**、不做任何基于归因的动作

## 七、常见错误（逐条自查）

| 错误 | 为什么错 | 正确做法 |
|---|---|---|
| 把 `possible` 写进"受影响资产" | 遏制范围虚高，白关业务 | 三级分列，处置不同 |
| 单源 IOC 就封禁 | 单源误报率高 | 标 `single-source`，只监控 |
| "行为相似"就归因组织 | 大量攻击者共用开源工具，同义性极低 | 低置信度禁止给组织名 |
| 写"可能""也许" | 不可操作 | 给等级，不给模糊词 |
| 不给反例 | 决策者无退出条件 | 归因/C2/`probable` 必须给 |
| 只给 CVSS 就定优先级 | CVSS 不含资产暴露面与业务重要性 | 结合暴露面 × 业务重要性 × 可利用性 |
| 扫描器输出当漏洞清单 | 未降噪 | 必须给"确认/未确认/误报"三类计数 |
| 不写观察窗口 | 无法判断"未复发"是否可信 | 写明窗口时长与是否覆盖攻击者活跃时段 |
| 因果当相关 | "A 先于 B"≠"A 导致 B" | 要主张因果必须给机制，否则标"时序相关，未证实因果" |

## 八、自检清单

- [ ] 每条结论都有**源 / 方法 / 结论**三元组吗？
- [ ] 漏洞类结论标了 `verified / inferred / speculative` 吗？
- [ ] `speculative` 有没有混进结论段？
- [ ] 影响范围**三级分列**了吗？有没有合并？
- [ ] 置信度分了**三个维度**吗？还是只写了个"高"？
- [ ] 归因 / C2 / `probable` 结论附**反例**了吗？
- [ ] 低置信度结论，我有没有据此做处置？（不该）
- [ ] 我用了"可能""也许"这类词吗？（换成等级）
- [ ] 我给了**观察窗口**吗？覆盖攻击者活跃时段了吗？
- [ ] 因果主张给了**机制**吗？还是只是时序？
- [ ] 攻击链的**断点（gap）**标出来了吗？有没有用推测接链？
- [ ] 我的结论能让决策者知道**该做什么动作**吗？
