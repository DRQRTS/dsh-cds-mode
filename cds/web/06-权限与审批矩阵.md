# 权限与审批矩阵

> **本文件回答一个问题：什么动作，谁做，要谁批。**
> **核心分界线：是否改变目标系统的状态**（见 `02-策略门.md` 第二节）。

---

## 一、总览矩阵

| 动作类型 | 执行者 | D-web1 | 用户权限 | 其他前置 |
|---|---|---|---|---|
| **只读查询**（读日志/配置/CMDB） | 各 Agent | 免 | 免 | —— |
| **分析产出**（报告/结论/方案） | 各 Agent | 免 | 免 | —— |

| **加检测规则**（不改状态，只加监控） | G-web1 | **需**（可预授权） | 免 | 回放误报率 |
| **限速 / 加挑战** | I-web2 | **需**（可预授权） | 免 | 业务归属已查 |
| **阻断特定路径** | I-web2 | **需**（可预授权） | 免 | —— |

## 二、按风险等级的三档

| 档 | 特征 | 例子 | 审批要求 |
|---|---|---|---|
| **低** | 不改系统状态，或改而无业务影响、可秒级回滚 | 加检测规则、限速、只读取证、加监控 | **D-web1 可预授权自动放行** |
| **中** | 改系统状态，有局部业务影响，可回滚 | 封 IP、切出站、删邮件、改配置 | **D-web1 + 用户权限** |
| **高** | 改系统状态，业务影响明显，或不可回滚 | 隔离主机、网段断连、数据删除、反击 | **D-web1 + 用户权限 + （涉业务）C-web4 评估** |

**预授权清单**：低档动作可在授权书里事先列明，D-web1 依清单自动放行，**但仍逐条落审计**。
**预授权不是"免审批"**，是"事先批过的批"。

## 四、双通过规则（最高风险的三个动作）

以下三类动作**必须` D-web1 允许 `+` 用户权限凭据 `双齐**才能执行：

1. **隔离主机 / 网段断连**
2. **数据删除 / 不可回滚动作**
3. **任何反击动作（I-web5 全部动作）**

**双通过的具体含义**：

```yaml
# 执行者必须同时持有两项凭据
gate:
  req_id: REQ-041-b
  decision: allow
  audit_ref: AUD-2026-0417-02
user_credential:
  id: UX-8891
  granted_by: <用户标识>
  granted_at: 2026-10-01T03:52:00+08:00
  scope: "隔离 10.0.20.14 与 10.0.20.31，时长 4 小时"
```

**缺任一项 = 未审批 = 拒收并回 `reject`。**
**口头同意不算凭据。** "用户说可以"必须有记录 —— 由晨通过 `ask_user_question` 获取，结果落 `.cds/decisions.md`。

## 五、"绝对不做"清单（不因授权而改变）

**这些动作无论授权书写得多宽，都不做：**

| # | 动作 |
|---|---|
| 1 | 入侵、破坏、篡改攻击者系统 |
| 2 | DDoS 或任何形式的流量攻击 |
| 3 | 植入后门或向对方系统投放诱饵 |
| 4 | 窃取对方数据（哪怕"只是看看"） |
| 5 | 攻击未明确列入范围的目标（含"同伙"） |
| 6 | 对任何自然人进行报复性行动 |
| 7 | 对第三方系统发起任何请求（除非明确列入范围且类型允许） |
| 8 | 伪造身份进行社会工程（授权演练的话术边界内除外，且不得索取真实凭据） |

**理由**：授权可以扩大"允许做什么"，**不能把犯罪行为变成合法行为**。
落入此清单的请求 → **拒收**并上报晨，由晨向用户解释。

## 六、自动化动作的边界

**G-web2 的剧本可以自动执行，但受三条约束**：

| 约束 | 要求 |
|---|---|
| **预授权清单** | 只自动执行清单内的低档动作 |
| **熔断三件套** | 速率上限 / 范围上限 / 一键停止 |
| **越界停下** | 一旦要做的动作超出清单，**停下要审批** |

**自动化不得成为绕过策略门的通道。** 剧本里每一步都要标明：自动 or 人工确认。
