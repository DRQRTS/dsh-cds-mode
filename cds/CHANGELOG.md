  - `dsh-plugin/cds-mode/locale/{zh,en}.json`、`icon.svg` — 插件管理器展示元数据

### 关键设计决定

1. **两个预设而非一个**：`dsh-experimental-*` 无稳定性承诺，若与 CDS 主体同预设，实验行激活失败会连带废掉整个 CDS。故 baseline 预设零实验依赖，保证 CDS 主体一定可用。
2. **不挂 `dsh-persona` 行**：身份由 `cds-mode` 插件注册；再挂 `dsh-persona` 会在同一作用域层产生两个同名 section，提示词注册表拒绝同层重名，结果是激活失败而非覆盖。
3. **11 份全文注入 + 12 份按需读取**：工作规则类进系统提示（约 44,930 字符），题库类（近 2000 行）只给路径。
4. **八条运行裁定写在插件里**（不写进语料）：规范不因运行环境改写，运行环境的收口放在运行环境里。裁定内容见 `dsh-plugin/README.md` 第 4 节。
5. **同伴频道用现成插件绑定**，不自研：`@deepseek-ai/dsh-experimental-agent-team` + `@deepseek-ai/dsh-experimental-tool-agent-team` 正是"子 Agent 之间直接对话、不经主 Agent 传话"的现成实现，符合本模式"若有现成插件则稍作修改后绑定"的要求。

### 缓存影响

- **v1.0.0 语料的缓存前缀未变动**，此前已装载的会话不受影响。
- 新预设的系统提示是一段新的、逐字节确定的文本（约 50,254 字符，含插件外壳）。同一份语料两次装载结果完全一致，已实测验证。
- 语料指纹写在提示词末尾的 `cds-mode corpus digest` 注释里，可用于核对"模型看到的"与"磁盘上的"是否同一份。
- **改语料 = 改前缀 = 本预设会话的提示词缓存失效一次**。插件用 `liveReload: false` 把这件事从"随时发生"改为"重启会话时发生"。

### 已知未决

- `preset-cds-team` 依赖 `dsh-experimental-*` 三个包，**无稳定性承诺**。若上游破坏性变更，该预设可能激活失败；`preset-cds` 不受影响，仍可正常使用 CDS 模式，同伴频道降级为协议第三层（文件频道）。
- 替换已安装的插件包**需要重启 dsh** 才能加载新的 JS 模块代；HMR 只让新 bundle 激活，不会换掉在跑的模块。
- 八条运行裁定是**规范的解释**，不是规范的替代。若裁定与规范正文冲突，以裁定为准；若要改裁定，需同步更新 `dsh-plugin/README.md` 第 4 节与插件内的 `RULINGS` 常量。

### 打包自检抓到的一个真 bug（v1.4.0 埋下的）

**自制 glob 的层级限制，第二次咬人。**

`package.json` 的 `files` 里写的 `cds/**/*.md`，被我那个自制 glob 翻译成 `^cds/.*/[^/]*\.md$` —— **`.*` 不匹配 `/`**，所以它**只能匹配一级子目录**。

后果：`cds/personas/web/`（36 份）和 `cds/web/`（新增的 8 份在根级，由 `cds/*.md` 兜住）里**深层嵌套的 36 份委任书全部漏出包**。

**修法**：

1. `files` 改用**明确的逐层模式**（`cds/*.md` / `cds/*/*.md` / `cds/*/*/*.md`），不再依赖 `**` 的自制翻译——**每个 `*` 只匹配一层，语义清楚，不会歧义**；

**这句话值得单独记住**：*定点检查证明"我关心的在"，全覆盖检查证明"没有我不关心的漏了"。* 前者拦不住后者的问题。

### 追补（同日）：新增 `.zip` 分发产物

用户反馈"官方上传要求是 .zip"。**`.zip` 不是 `.tgz` 换扩展名** —— 两者是完全不同的格式，所以不能用改扩展名糊过去。

**查清了一件事**：DSH 的 `installBundle` 接受 **registry 包 / git 地址 / tarball / 绝对路径**，**不接受 `.zip`**。所以"官方要求 zip"是**分发/上传平台**那一侧的要求，与 DSH 的安装机制无关。两者不冲突：zip 给平台，对方解压后用目录路径安装。

**实现**：手写了一个**零依赖的最小 ZIP 写入器**（`_zip.mjs`，约 120 行，本地文件头 + 中央目录 + EOCD，deflate 压缩，UTF-8 文件名标志）。理由是本包的硬规则——**零外部依赖**——调 `Compress-Archive` 或 `zip` 会把构建绑到宿主工具上。

`_pack.mjs` 现在**用同一份已校验的文件清单同时产出两种格式**，并做了**三重验证**：

| 验证 | 用什么解压 | 结果 |
|---|---|---|
| tar 解压核对 | 系统 `tar` | 97 文件、90 语料与源一致 |
| zip 解压核对 | 系统 `tar -xf` | 97 文件逐字节一致 |
| zip 独立核对 | **.NET `ZipArchive`**（PowerShell `Expand-Archive`） | 97/97 逐字节一致 |

> **手写的写入器不能自己给自己背书。** 所以 zip 必须用**系统解压器读回来**才算验证过——而且用了两个不同的实现（GNU tar 的 zip 支持 + .NET ZipArchive），两个都认。

**过程中踩的一个坑（值得记）**：构建连炸两次，报 `writeUInt32LE` 收到 `-2119958528`。

我**第一次猜错了方向** —— 去改 `crc32` 的返回值（以为是有符号问题），改完照旧报错。真正的原因是同一行的另一处：`0o100644 << 16` 在 JS 里是**有符号 int32**（`0x81A40000` 最高位为 1），而 ZIP 的外部属性字段按无符号写。

**教训：报错给的是行号，不是原因。** 该先读那一行再动手，而不是先猜一个"常见原因"然后去改别处。

已加 **B5 组 8 项断言**把 ZIP 写入器纳入回归：签名、EOCD 条目数、中央目录偏移、**CRC32("hello") = 0x3610a686（已知标准值）**、外部属性无符号、deflate 有效性，另加中文路径往返。并新增 `_compare-extract.mjs` —— 一个可复用的"解压物 vs 源"逐字节比对器，可指定任意解压目录。


它要求 `Config` 是一个 **schemastery / Standard-Schema 对象**（`z.object({...})`，`dsh-persona` 就是这么写的）。我导出的是手写的普通对象 `{ type: 'object', properties: {...} }`——它没有 `~standard`，于是 `.validate` 是 undefined，**在插件启动阶段抛错**，并被 `agent-preset-registry` 转成用户可见的「加载失败」。

**修正**：**去掉 `Config` 导出**。没有 schema 时 cordis 原样返回 config，而 `apply()` 本来就自己兜底默认值 + 自行校验（`corpusDir` 读不到、超 `maxChars` 都有指名道姓的报错），比 schema 校验的提示更有用。副作用：插件管理器不再能按 schema 展示/校验这三个字段——已知取舍。

### 错误二：`pwsh` 工具名在同一作用域注册两次

我从 `minimal` 预设抄了 `persistent-shell` 组（它注册**常驻**的 `pwsh`/`bash` 工具），同时又保留了 `preset-standard` 用的 `tool-pwsh`（**瞬时**工具）。**两套都装，工具名都是 `pwsh`**，注册表直接拒绝。

**修正**：删掉 `persistent-shell` 组，只保留 `tool-pwsh` —— 与 `standard` 预设一致。

### 验证（29 项断言，全部通过）

新增了**工具重名审计**：把每个预设作用域内所有启用行注册的工具名收集起来查重复。旧版校验没这一项，所以漏掉了这个 bug；现在它被制度化地挡住了。

**类型**：**修正**（修复导致两个预设全部「加载失败」的根因）

### 根因

`index.js` 里有一行：

```js
import { PERSONA_PREFIX_SECTION } from '@deepseek-ai/dsh-system-prompt'
```

**这个包在 profile 的 `node_modules` 里不存在。** 实测：

```
profile\node_modules 顶层  =  .modules.yaml / .pnpm / @local    ← 没有 @deepseek-ai
从 bundle 真实目录 import '@deepseek-ai/dsh-system-prompt'  →  ERR_MODULE_NOT_FOUND
```

profile 用 `nodeLinker: hoisted`，而 DSH 自带的包**不在 profile 的 node_modules 里**。这个裸包名 import 解析失败 → `cds-mode` 行激活失败 → **两个预设都挂这一行，于是两个都标红「加载失败」**。

这是设计错误：为了一个字符串常量，引入了一个包依赖。

### 修正

`PERSONA_PREFIX_SECTION` 改为字面量 `'deployment:persona-prefix'`，源码注释里记了原因。**插件现在只 import `node:` 内建，零外部依赖**，从 bundle 真实位置加载已实测通过。
