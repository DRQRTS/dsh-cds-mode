# 自救模式 · 省钱部分：缓存命中率优化

> CDS 模式集成「自救模式（省钱部分）」的全部相关能力。
> 核心手段：**提示词约束** + **思维链控制**，提高缓存命中率，降低 token 消耗。

---

## 一、为什么缓存会失效（先理解机制）

上下文缓存（prompt caching）按**前缀匹配**工作：只有当本次请求的开头部分与上次请求**逐字节一致**时，前缀部分才能命中缓存。

因此，缓存失效的**唯一原因**是：**前缀发生了变化**。

### 前缀杀手清单（按破坏力从高到低）

| # | 杀手 | 例子 | 破坏力 |
|---|---|---|---|
| 1 | 系统段插入动态内容 | 在系统提示里写"当前时间 10:23:45"、"当前是第 3 轮" | 致命：每次请求全失效 |
| 2 | 人格卡顺序变化 | 这次先放 A 组，下次先放 B 组 | 致命 |
| 3 | 把长文件全文塞进上下文 | 把 `00-整合资料.md` 全文贴进每次调用 | 严重：浪费且前端重复 |
| 4 | 把对话历史整体重排 | 每次"总结一下"后改变历史顺序 | 严重 |
| 5 | 同一人格开新会话 | C1 每轮都新建会话 | 严重：每次都从零开始 |
| 6 | 在系统段用随机/自增 ID | `task_id: T-001` 放在系统段开头 | 中等 |
| 7 | 工具定义顺序变化 | 动态拼装工具列表 | 中等 |
| 8 | 无意义的寒暄追加 | 每轮加一句"你好，请继续" | 轻微但累积 |

## 二、提示词约束（前缀稳定化）

### 规则 P1：前缀分层，动静分离

上下文**必须**按以下顺序组织，且**从上到下流动性递增**：

```
[ 第 1 层：绝对静态 ]  ← 永不变动，缓存主战场
  1. CDS 模式核心契约（CORE.md 全文）
  2. 人格卡（按固定顺序：chen → A1..A4 → B1..B4 → C1..C4 → D1..D6 → E1..E3）
  3. 协议文件（peer-channel.md → artifacts.md → bug-taxonomy.md）
  4. 缓存经济规则（本文件）

[ 第 2 层：项目静态 ]  ← 同一项目内不变
  5. .cds/requirement.md 的「需求编号列表」（只有编号与一句话，不含问答原文）
  6. .cds/frozen-list.md

[ 第 3 层：轮次半静态 ]  ← 一轮内不变
  7. 本轮的 task 结构
  8. 本轮需要的产物**路径清单**（不是内容）

[ 第 4 层：动态 ]  ← 每次可变，放最末尾
  9. 当前子任务指令
  10. 同伴频道未读消息
```

**硬约束**：第 1 层与第 2 层**禁止出现任何随时间/轮次变化的内容**。

### 规则 P2：禁止在静态层使用动态插值

```diff
- 以下是第 3 轮的任务（时间：2025-01-01 10:23）
+ 以下是本轮任务
```

```diff
- 人格清单（当前活跃 7 人：A1, A2, ...）
+ 人格清单（见 CORE.md 第二节）
```

时间、轮次、活跃人数、未读计数、随机 ID 一律放到**第 4 层**或**不放进上下文**（落盘即可）。

### 规则 P3：长资料只传路径

```diff
- 【调研资料全文】<20000 字的 00-整合资料.md 全文>
+ 【调研资料】design/00-设计初稿.md 的输入为：research/00-整合资料.md
+   读取方式：只读取第 3 节（冲突与未决项）与第 7 节（移交说明）
```

**例外**：若某人格的**唯一职责**就是读全文（如 A4 汇总），则只在该人格的**单次调用**中放入全文，且**不重复放**。

### 规则 P4：人格卡顺序与内容冻结

- 人格卡一经写入 `cds/personas/`，**顺序与措辞冻结**；
- 修改人格卡 = 全局缓存失效，必须**批量修改、一次到位**，不许零散微调；
- 修改后必须记录在 `cds/CHANGELOG.md`，并注明"本次修改导致全局缓存失效一次"。

### 规则 P5：工具定义稳定

- 子 Agent 的工具集**固定**，不做按需增减；
- 若必须增减，集中在**同一批次**完成。

### 规则 P6：禁止寒暄与确认性追加

```
禁止：好的，我明白了。现在让我们开始第二步。
禁止：收到！下面我将为你...
```

直接进入工作内容。这既是**省钱**，也是 **D4 的 AI 味治理要求**（一举两得）。

## 三、思维链控制（把"想"也变成可缓存的）

### 规则 T1：思考过程结构化模板

每个子 Agent 的思考遵循固定骨架，骨架不变，只有内容填进去：

```
1. 我收到的输入是什么（路径清单）
2. 门禁是否满足（是/否 + 缺什么）
3. 我要产出什么（路径 + 结构）
4. 我的关键决定与理由（≤5 条）
5. 我的未决项
6. 移交谁
```

**好处**：骨架固定 → 前缀稳定 → 命中缓存；同时防止思维发散导致的 token 浪费。

### 规则 T2：禁止在思考里复述已落盘内容

```
禁止：我读了 requirement.md，用户要求是……（复述 500 字）
允许：requirement.md 已读。关键约束 R-014、R-027 与本任务相关。
```

### 规则 T3：一次想清楚，不要反复"再确认一下"

多轮"我觉得……不对，应该是……"会显著增加输出 token 且降低质量。要求：
- 若不确定，**直接列为未决项**，不要反复推演；
- 推演上限：同一问题不超过 **2 次** 修正，第 3 次直接标为未决。

### 规则 T4：思维链不入产物

思考过程不进最终交付文件（产物只放结论与依据）。思考用一次性输出，产物可复用。

## 四、会话与调度约束

### 规则 S1：一人格一会话

> **先澄清一处容易误读的地方**：这条说的是"**同一实例**的连续任务复用同一会话"，**不是**"禁止同编号多实例"。
> 同编号**并发多实例是允许且鼓励的**（见 `CORE.md` 第二节与第六节第 3 条）——**并发实例各开各的会话**，它们本来就不该共享历史。
> 本规则约束的是：**别给同一个人格的同一个任务线反复开新会话。**

| 做法 | 效果 |
|---|---|
| 同一实例的多个任务追加到同一会话 | 命中缓存，且该实例保有上下文 |
| 每轮新建会话 | 缓存全失，且丢失上下文 |
| 同编号**并发多实例**，各开各的会话 | **正解**——它们干的是互斥切片，不该共享历史 |

**例外**：会话长度超过必要阈值（比如该实例已积累了大量与本任务无关的历史）时：
1. 先把结论写入产物文件；
2. 在新会话中**只带产物路径 + 静态层**继续；
3. 记录到 `cache-notes.md`。

### 规则 S2：并行人格的前缀共享

A1/A2/A3 并行工作时，三者的**静态层完全一致**（同一套 CORE + 协议 + 缓存规则），只有最后的任务指令不同。这样三者的缓存前缀互相受益。

**做法**：把"共同前缀"作为独立的一次上下文，然后各自追加自己的任务。

### 规则 S3：批处理而非逐个唤醒

```
差：晨 → A1（等）→ A2（等）→ A3（等）
好：晨 → [A1, A2, A3] 并行 → A4
```

### 规则 S4：避免中间唤醒

不要为了"告知进度"而唤醒人格。进度写入 `state.md` 即可，人格在下次正常唤醒时读取。

## 五、度量与台账

### 必须记录的内容（`.cds/cache-notes.md`）

```md
## 缓存台账

| 轮次 | 缓存前缀是否变动 | 变动原因 | 影响的人格 | 估计额外成本 | 已采取的缓解 |
|---|---|---|---|---|---|
| 1 | 否 | — | — | — | — |
| 2 | 是 | 修改了 B3 人格卡的视觉基线 | 全员 | 一次全局重算 | 已知，接受 |
```

### 度量指标

| 指标 | 定义 | 目标 |
|---|---|---|
| 前缀稳定率 | 本轮请求中前缀未变动的比例 | ≥ 95% |
| 全文搬运次数 | payload 中出现文件全文的次数 | 0（A4 汇总除外） |
| 会话新建次数 | 同一人格新建会话的次数 | 每项目 ≤ 1 |
| 平均上下文冗余度 | 上下文中与本轮任务无关的比例 | < 20% |
| 未读消息滞留轮次 | inbox 未读消息平均滞留轮次 | ≤ 1 |

**度量责任人**：A4（产物侧）+ D6（统计侧）；**执行责任人**：晨。

## 六、成本熔断联动

见 `workflow/04-escalation.md` 第五节。触发成本警报时的固定动作：

```
1. 检查是否存在"全文搬运"  → 有则立即改为路径引用
2. 检查静态层是否有动态插值 → 有则移出
3. 检查是否有人格频繁新建会话 → 改为追加
4. 检查是否有重复调研 → 由 D6 标记，合并任务
5. 检查是否有人格空转 → 移除该人格调用
```

## 七、省钱自检清单（晨每轮执行）

- [ ] 我的静态层（CORE + 人格卡 + 协议 + 本文件）与上一轮**逐字节一致**吗？
- [ ] 我有没有在静态层写时间/轮次/ID？
- [ ] 我传的是**路径**还是**全文**？
- [ ] 并行人格共享同一前缀了吗？
- [ ] 同一人格是**追加**会话还是新建会话？
- [ ] 我有没有为了"礼貌"加无意义的确认句？
- [ ] 本轮有没有重复调研已知结论？
- [ ] `cache-notes.md` 更新了吗？

## 八、与其他模式的集成说明

| 集成对象 | 本文件对应的部分 |
|---|---|
| **标准模式** | 静态层的规范性与顺序性来自标准模式的确定性要求 |
| **创造模式** | 个性化（A3/B1）产生的**资料**在静态层之外，不破坏前缀 |
| **自救模式（省钱）** | 本文件全文 |

**一句话原则**：**把不变的东西放在最前面，把变化的东西放在最后面，把很大的东西放在外面（文件里）。**
