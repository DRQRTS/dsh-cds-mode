# 提问机制：生成式提问（取代"照题库念"）

> **本文件是提问的总纲。** `00-calibration.md`、`01-new-project-280.md`、`02-takeover-120.md`、`03-followup-10.md` 都只是**素材库**，服从本文件。

---

## 一、为什么要有这一份

CDS 模式最初的错误做法：给晨 277 道题，晨从 Q001 开始往下念。

结果有三个：

1. **问题不专门**。用户说「内部工具、就我们组 5 个人用」，晨还在问「要不要接支付」「需要 ICP 备案吗」。
2. **问题不灵活**。用户答了 A，本来该追问 A 的细节，晨却跳到下一题 B。
3. **用户跑掉**。连问 40 道与己无关的题，谁都会关窗口。

**根子在于把"覆盖面"当成了"脚本"。** 题库的用途是**保证不漏**，不是**规定顺序**。

---

## 二、三层提问结构

```
第一层：判定（决定问什么）
    从用户已有信息中读出：项目类型、规模、专业度、已排除项
        ↓
第二层：生成（现场造题）
    依据判定结果，从九大提问域中挑出「还没覆盖、且对后续决策有影响」的域
        ↓
第三层：素材（造不出来时兜底）
    打开题库，找同类问法参考，或直接取用
```

**关键是第二层。** 题库只在第三层出现。

---

## 三、判定层：从已知信息读什么

每收到一批回答，晨先更新这张判定表（写在 `.cds/state.json` 的 `questioning` 段）：

| 判定项 | 取值 | 它决定了什么 |
|---|---|---|
| 项目类型 | web / app / 桌面 / CLI / 插件 / 内容 / API / 数据 / 游戏 / 企业内部工具 | 哪些提问域**整域跳过** |
| 专业度档位 | L1 / L2 / L3 / L4 | 用词、题量、每题的选项抽象度 |
| 规模 | 极小 / 小 / 中 / 大 | 要不要问运维、备份、灰度、多环境 |
| 商业性质 | 免费 / 收费 / 内部 / 开源 | 要不要问定价、退款、发票、协议 |
| 部署面 | 本地单机 / 内网 / 公网 | 要不要问备案、域名、CDN、限流 |
| 受众地域 | 单地区 / 全国 / 跨国 | 要不要问时区、多语言、合规 |
| **已排除项** | 列表 | **绝对不再问的东西** |
| **待澄清项** | 列表 | 下一批必须问的东西 |

**「已排除项」是最有价值的一栏。** 用户说"不需要登录"，就把「账号、权限、会话、密码重置」整块划掉，永不回头问。

## 四、生成层：现场造题的四个动作

### 动作 1 · 把模板问题"**具体化**"

模板是抽象的问法。真问题是把它**接到这个项目的名词上**。

| 模板（题库里的样子） | 现场生成的问法 |
|---|---|
| 需要登录吗？ | 你说"同事都能看"——是**所有人看同一份**，还是**每人只看自己那份**？ |
| 数据量多大？ | 你提到"一个年级的学生"。一个年级大概多少人？最多到多少？ |
| 要不要导出？ | 你现在的流程最后一步是把表发给教务处。要**直接生成那个表**，还是导出后你自己改？ |
| 通知方式？ | 老师平时看微信还是看邮件？决定了通知发哪儿。 |
| 需要深色模式吗？ | 你说"晚上在家批作业"——那深色模式就不是可选的了，对吗？ |

**判据**：把一个问题的答案拿掉，如果你后续的动作完全不变，那这个问题就是模板残留，删掉。

### 动作 2 · **追问**用户上一批答案里的模糊处

用户答得越具体，追问越值钱。**一次只追问一层**，不要连环炮。

```
用户：要能导入学生名单。
晨：追问 → 名单从哪来？① 教务系统导出 ② 手工 Excel ③ 我粘贴文本
用户：教务系统。
晨：追问 → 那个系统能给你什么格式？① Excel 文件 ② 能给我一个下载链接
            ③ 我每次手工点导出（说明：这决定了我做成"上传文件"还是"定时抓取"）
```

**每个追问都必须带一句"为什么问"**——当追问看起来像在质询时，说明理由能让用户配合。

### 动作 3 · 用**用户的词**造题

用户说「工单」，你就说工单，别说「ticket 实体」。用户说「我们组」，你就说「你们组」，别说「租户」。

**术语反向适配**：用户用错术语时，不要纠正他，先用他的词把问题问清楚，拿到答案后再在需求摘要里换成正确定义，并注明「用户原话」。

### 动作 4 · 敢于**跳过**

九大提问域是**检查表**，不是必修课。某一域明显不适用就整块跳过，并在 `.cds/requirement.md` 记一行：

```
- D3 商业性质：整域跳过。理由：用户明确"单位内部工具，不涉及任何收费"（来源 Q021C）。
```

**跳过必须留痕**，这样别的人才格不会回头再问一遍。

## 五、题量与节奏

| 阶段 | 题量 | 节奏 |
|---|---|---|
| 校准 | 固定 5 题（接手项目 +2） | 一次给完 |
| 需求采集（新项目） | **70–280，按需浮动** | 每批 ≤5 题 |
| 需求采集（接手项目） | 通用 25–40 + 接手专属 | 每批 ≤5 题 |
| 每次新要求 | 固定 5–10 题 | 一次给完 |

**题量按需浮动的意思是**：

- 信息够了就**停**。不要为了凑够 70 题硬问。
- 用户说「你决定」，记 `delegated`，**往下走**。
- 项目很大、用户很配合、每问一句都能改变设计 → 可以到 280。
- 项目很小、用户很忙、需求已经很明确 → 70 甚至更少。

**硬下限是 70 吗？不是。** 70 是"如果这个项目确实需要问这么多"的参考值。**真正的硬约束是：不许在不理解需求的情况下写代码。**

## 六、提问的呈现规范

1. **一律用 `ask_user_question` 工具**（CORE 铁律 L9）。不许散文提问。
2. 每批 **≤5 题**。超过 5 题，用户会开始乱点。
3. 每题**必须带出口**：「其他 / 我来描述」。没有出口的选择题 = 逼用户在错的选项里挑。
4. **可多选的题要标出来**（如「可多选」）。
5. 选项**互斥且穷尽**。别出现「A. 要 B. 不要 C. 看情况」这种把"看情况"塞进选项的偷懒做法——那是没想清楚。
6. 给**建议**时标明是建议：`（我建议 A，理由：……）`，不要混在选项里冒充事实。
7. **不要在选项里塞长句**。选项超过 20 字就该拆成两题。

---

## 七、答完之后必须做的三件事

1. **一句话复述**并请用户确认：
   > 我理解你要的是 ____，不许动 ____，验收标准是 ____。对吗？
2. **写进 `.cds/requirement.md`**，编号 `R-xxx`，每条可追溯到具体题号与选项。
3. **更新判定表**：这一批答案排除了什么、新引出了什么待澄清项。

**门禁**：用户未确认需求摘要，不得进入下一个节点。

---

## 八、自检（每批问题发出前，逐条过）

- [ ] 我用了 `ask_user_question` 工具吗？
- [ ] 这批问题里有几个是**换任何项目都能原样问**的？有几个就删几个。
- [ ] 有没有问已经被用户排除过的东西？（回看"已排除项"）
- [ ] 每题都有「其他」出口吗？
- [ ] 我用了用户的词，而不是我自己的术语吗？
- [ ] 这批问完之后，我能说出"接下来我要做什么"吗？说不出来就是问偏了。
- [ ] 题数 ≤5 吗？
- [ ] 有没有哪一题的答案，对我的后续动作毫无影响？有就删。

## 九、反例：什么叫做错了

| 错误做法 | 为什么错 |
|---|---|
| 从 Q001 开始顺序念到 Q070 | 把检查表当脚本，用户会在第 15 题放弃 |
| 用户说"内部工具"，还问支付和发票 | 没有维护「已排除项」 |
| 用户答"要导入学生名单"，直接跳到下一题 | 丢掉了最值钱的追问机会 |
| 问"你需要什么样的架构？" | 把技术决策推给用户，而且这个问题本身没有可答性 |
| 一次问 12 题 | 用户乱点，数据不可用 |
| 选项是「A. 是 B. 否」没有出口 | 用户被逼说谎 |
| 问完 70 题，说不清需求是什么 | 问了但没听 |
| 用户说"你决定"，仍反复确认 | 无视 `delegated`，浪费用户耐心 |

## 十、与题素材库的关系（一句话）

> **题库给你"不遗漏"的保障，不给你"问什么"的答案。**
> 每一次提问，都应该是**为这个项目、在这个时刻、因上一句回答**而生成的。
