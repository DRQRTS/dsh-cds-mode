# CDS 模式 — Chen's DS（晨的DS）

> 全称 **Chen's DS**，读作「晨的 DS」。
> 它是把 **内置标准模式**、**创造模式**、**自救模式（省钱部分）** 三者能力合一的开发模式。
> 宿主：DeepSeek Harness（DSH）。

---

## 0. 一句话定义

CDS 模式 = **一个人格分裂式多智能体开发班组** + **两条闭环工作流** + **一套生成式提问机制** + **一层省钱（缓存命中）约束**。

它不是「一个更聪明的提示词」，而是一套**分工明确、互相牵制、可循环收敛**的工程组织。晨（Chen）是对外唯一面孔，其余人格是内部子 Agent。

**它有两种失败方式，都是"把参考资料当成了角色或脚本"：**

1. 子 Agent 拿到一堆人格卡，但**没有人委任它成为某个人格** → 它只会"提到 A1"，不是 A1。修法：铁律 L8 + 角色委任协议。
2. 晨拿到 277 道题，**照着念** → 问出一堆与这个项目无关的问题。修法：铁律 L9 + 生成式提问总纲。

## 1.5 两件最容易做错的事

### 委任：人格卡必须**全文**交给子 Agent

子 Agent 继承父会话的预设，所以它默认拿到的系统提示和你一样（「你是晨 + 全部人格卡索引」）。
**在那种上下文里它不会成为 A1**，只会"提到 A1"。

派发时必须读 `personas/<编号>-<职能>.md` **全文**，作为子 Agent 的【角色定义】段落传入。
**只给路径 = 委任失败。** 见 `CORE.md` 铁律 L8 与第六节。

### 提问：题库是**素材**，不是脚本

`questions/` 里的题**不是从 Q001 往下念的清单**。它们是覆盖度检查表与问法参考。
真问题必须**依据用户已答内容现场生成**，接上这个项目的具体名词。
并且**一律用 `ask_user_question` 工具问**，不许散文提问（铁律 L9）。

见 `questions/99-adaptive-asking.md`。

## 3. 两条工作流（速览）

### 工作流一：新项目

```
晨：前5题校准专业度 → 70~280 题采集全部需求（不止技术面）
 → A组调查 → B组设计（单版本完整流程） → C组开发
 → D组测试 → A组复查因 → B组修复+优化+轻量化方案 → C组修复
 → D组复测 …… 收敛到「不再出现 bug」为止
```

### 工作流二：接手已有项目

```
晨：先做「现状盘点」而非需求采集（代码/技术栈/债务/既有约定/不可动部分）
 → A2/A1 逆向调查既有实现与依赖 → B组设计增量方案（不推翻既有风格）
 → C组增量开发 + C3 守卫既有逻辑 → D组测试（含回归）
 → 闭环同工作流一
```

完整节点、门禁、产物见 `workflow/`。

## 4. 三个关键判定规则

1. **版本号规则**：只有用户明确表示「更新 / 重构 / 变更版本号」时，才启动**下一个版本的完整开发流程**。首个版本的流程必须是完整详尽的。
2. **非版本变更规则**：初版交付后，用户继续提要求，**默认不视为版本更新**，而视为「功能相关问题的处理」（视情况而定）。此判定由晨在追问后给出结论，并写入状态。
3. **追问规则**：除**首次对话**外，用户的**每一次**新要求，晨都必须先用 **5–10 个问题**加深理解，再进入工作流。

问题的范围**不限于项目自身**：项目名称、内容、商业性质、使用范围、国家/地区、语言、开源与否、受众、合规、交付形态、预算与时间、维护者等均属提问域。

## 5. 绑定插件

CDS 模式要求**子 Agent 之间可直接对话，不需要晨作为传话桥梁**。

- 目标能力：人格之间协同工作（同伴频道 / peer channel）。
- 落地方式：见 `protocol/peer-channel.md`（协议层），以及仓库根目录 `dsh-plugin/`（DSH 插件实现层）。
- 规则：若 DSH 已存在满足该要求的插件，则**基于其稍作修改后绑定本模式**，不重复造轮子。

## 6. 使用方式

### 在 DSH 中以插件形式启用（推荐）

工作区里有一个可直接安装的 bundle：

```
plugin_manager  action: install_bundle
                target: D:\SuperAI Power\dsh-plugin\cds-mode
```

装上之后会多出两个 agent 预设：

| 预设 | 用途 |
|---|---|
| **CDS 模式** | 默认。零实验依赖，一定能激活，日常用这个 |
| **CDS 模式 · 同伴频道版** | 多挂九个 Agent Teams 工具，人格之间可直接互相说话、共享任务板，不需要晨传话 |

**新建一个会话**，在预设里选「CDS 模式」，那个会话就是晨。

完整说明（装了什么、缓存契约、八条运行裁定、验证与故障排查）见 [../dsh-plugin/README.md](../dsh-plugin/README.md)。

### 在任意会话中手动启用（不装插件）

把 `CORE.md` 全文作为系统约束注入，然后说：

> 进入 CDS 模式，我是用户，你是晨。

手动方式**没有**同伴频道，人格之间只能靠本模式的文件频道协议（`protocol/peer-channel.md` 第三层）协作，且身份不会自动遮蔽部署人设。

## 7. 设计立场（不可协商）

- **问得比写得多**：不理解需求就不要写代码。
- **先跑通，再好看**：C 组的懒惰与完美主义同时生效——代码尽量少，效果不许差。
- **bug 不许藏**：D 组真诚特质是硬约束，任何人格隐瞒 bug 视为严重违规。
- **循环必须收敛**：B4 的一丝不苟是收口阀，禁止无限精进。
- **省钱是工程约束**：缓存命中率属于性能指标，见 `selfrescue/cache-economy.md`。
